# Наставник — карманный свод и печатные материалы

Комплект для наставника двух братьев (8 и 10 лет): правила, протоколы типовых ситуаций,
план на 90 дней и концепция. Плюс печатные бланки и памятки для папы и мамы.

**Адрес после публикации:** https://artignat2000.github.io/mentor/ (телефон, офлайн, «На экран Домой»)

## Сборка

Нужен Python 3.9+ и, для PDF, пакеты из `requirements.txt`.

```bash
python3 build_print.py   # печатные PDF → print/ и docs/print/
python3 build_site.py    # страница        → docs/index.html (+ nastavnik.html в корне)
python3 make_pack.py     # иконки, манифест, sw.js, zip
```

Порядок важен: `build_site.py` вставляет на главную ссылки на те PDF, которые уже собраны,
а `make_pack.py` считает версию офлайн-кэша из содержимого `docs/index.html` — поэтому после
любой правки телефоны подтягивают новую версию сами, вручную версию поднимать не нужно.

Для PDF нужен шрифт DejaVu с кириллицей (Debian/Ubuntu: `sudo apt install fonts-dejavu-core`).
Если шрифта нет рядом с системой, положите `DejaVuSans*.ttf` в папку `fonts/`.

## Публикация (GitHub Pages) — включить один раз

В репозитории всё готово: папка `docs/` с `.nojekyll`, страницей, иконками и PDF.
Осталось включить хостинг (это делает владелец репозитория, ~30 секунд):

1. Открыть https://github.com/ArtIgnat2000/mentor/settings/pages
2. **Source:** *Deploy from a branch*
3. **Branch:** `main`, папка **`/docs`** → **Save**
4. Через 1–2 минуты страница будет по адресу https://artignat2000.github.io/mentor/

Дальше после каждого `git push` в `main` сайт пересобирается сам. Затем на телефоне:

1. Открыть https://artignat2000.github.io/mentor/ **в Safari** (не в браузере Telegram).
2. «Поделиться» → **На экран «Домой»** → Добавить.
3. Значок на домашнем экране открывается без адресной строки и работает офлайн
   (service worker кэширует страницу и иконки).

Файл `docs/.nojekyll` создаётся автоматически — без него GitHub Pages прогоняет папку через Jekyll.
Если в настройках Pages выбрана другая ветка (например, рабочая ветка сессии), сайт всё равно
работает, но живёт с неё; для постоянной публикации источник должен быть `main` + `/docs`.

Если страница открывается, но показывает старую версию: потянуть вниз для обновления;
ещё раз — закройте и откройте приложение с домашнего экрана.

## Как вносить правки в содержание

1. Правите markdown-файлы (источник правды).
2. `python3 build_site.py && python3 make_pack.py`.
3. Коммит и пуш — сайт обновится сам.

Если поменялись формулировки в печатных материалах — их текст лежит в `build_print.py`
(константы `RULES5`, `STOP10`, `PHRASES3`, `SCALE`, `SELF_CHECK` и тексты памяток),
после правки: `python3 build_print.py && python3 build_site.py && python3 make_pack.py`.

## Что в этом комплекте намеренно не сделано

Нет баллов, звёздочек, рейтингов между братьями и «доски позора»: любая система, где
братья соревнуются, усиливает ровно то, с чем мы боремся. Это решение, а не недоделка.
